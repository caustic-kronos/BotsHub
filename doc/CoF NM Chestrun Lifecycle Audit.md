## Direct-exit audit

- `TravelToOutpost($ID_DOOMLORE_SHRINE, ...)` occurs only during setup/entry preparation and is followed by live Gron resolution and Cathedral map-load verification before route movement.
- The one-time return-point priming trip enters CoF, immediately crosses back to Doomlore, and verifies the Doomlore map before marking setup complete. It is outside the measured run timer.
- Normal `ResignAndReturnToOutpost($ID_DOOMLORE_SHRINE)` occurs after `CoFChestFarmLoop` returns and after every opened chest has already completed its exact-drop transaction or marked the run loot-blocked.
- Emergency `Resign()` exists only in the 96-second watchdog. It first marks `$cof_chest_watchdog_expired`, logs the forced exit, and makes the benchmark fail.
- There is no `Map.Travel`, dungeon level exit, final-chest return choice, reward turn-in, or loop/menu jump in this owned AutoIt runner.

## Side-chest transaction conclusion

No runner change is required by this audit. The current transaction already prevents a normal successful cycle from resigning before a desirable drop's exact ground-agent ID disappears. Full inventory prevents spending the lockpick. An unobserved or unresolved new drop fails the run. Policy-rejected loot is deliberately outside the intended pickup set, matching the selected BotsHub loot configuration.

This conclusion is an offline structural audit. It does not replace in-game validation of chest prompts, item assignment timing, pickup behavior, watchdog behavior, or return-point priming.
